## 4. Protocol extension (dispatch section 0.3)

The existing ResultSectionHeaderV2 has no round-1/round-2 dual DONE fields, so the
protocol was EXTENDED per dispatch: PROTOCOL_VERSION unchanged; the free
_reserved u16 slot in the result header (offset 0x06..0x08) carries the
round-flags word:

- ROUND1_DONE=0x0001, ROUND2_DONE=0x0002, ROUND_FLAGS_KNOWN=0x0003,
  RESULT_HEADER_ROUND_FLAGS_OFF=0x06;
- validate_layout() does NOT check this field -> frozen R5-R2 validators keep
  identical semantics (the _reserved slot always passed);
- round-2 DONE requires both bits (ROUND1_DONE|ROUND2_DONE) -> forging round-2
  while skipping round-1 is impossible at the protocol layer;
- PENDING/ABORT states carry round-flags == 0;
- new APIs: set_round_flags / round_flags / validate_round_flags.

See design doc sections 1-2 (fields/states/sequence/digest/bounds/failure
transition table).
