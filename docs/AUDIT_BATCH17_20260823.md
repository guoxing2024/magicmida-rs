## 4. P0-1703-1：v2 magic/version detection 会越界读取

WO-1505 规定 v1 blob 为 0x30，v2 从偏移 0x30 追加 magic/pointer/len，总长 0x48；runtime 读取 offset 0x30 判断版本。

真实 MidaAntidebugInitialize 只有一个 MidaInitParams pointer 参数，没有 blob length/struct size。v1 caller 只保证 0x30 bytes。runtime 无法安全知道 offset 0x30 是否可读，直接读取属于越界读/未定义行为，破坏 v1 字节兼容。

必须在 v1 已有范围内增加安全 size/version 语义，或提供独立 versioned entry point/envelope。不能通过读取 v1 末尾之外的 magic 猜版本。

## 5. P0-1703-2：v2 magic 的 little-endian 常量错误

WO-1505 写 magic_v2 = 0x4D494441325032，并标注为 MIDA2P2 LE。

该数值按 little-endian 写入的字节是：

32 50 32 41 44 49 4D 00 = 2P2ADIM\0

不是 ASCII MIDA2P2\0。必须提供正确的 0x30/0x48 完整 hex fixture、encoder/decoder 伪代码和 endian test vector。

## 6. P0-1702-3：probe window 边界不可实施

WO-1702 使用 mida_probe_window 返回 start/end，并声称存在 mida_probe_read_end，但 header 没有该符号或定义。

还缺少 linker section、explicit marker 或 generated symbol 合同；“MSVC 保证同一 obj 内函数地址有序”不能证明函数末地址，也不能阻止链接器布局/优化变化。

同时，__movsb 与“两条 8-byte load”并存，实际 faulting RIP 集合没有冻结。必须选择显式 markers/section，或取消 RIP window attribution 并用 active-thread + call-token 归属。
