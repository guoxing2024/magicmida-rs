## 二、Round 1:执行驱动覆盖率测量

1. **身份预检硬门**(同前;mismatch 即停不耗轮);
2. **观察宿主**:调试启动受保护输入(vault 对象),`MIDA_GTO_NO_BYPASS=1`;
3. **双相测量协议**(区别于 R1/R2 单点采样):
   - **A 相(时间动态)**:锚点页(各节起始 4KB,沿用旧口径)每 500ms 连续采样;
   - **B 相(空间覆盖)**:在关键时刻做全节条带扫描 —— `.rdata2`(24.5MB)每 64KB 取 4KB 样本
     (~381 点)、`.rdata0`(21MB)同理(~330 点)、`.pdata` 全量;扫描时点至少:
     t0(进程就绪)/ 主窗口出现 / +60s / +180s / 观察结束;
   - 覆盖率定义:B 相扫描中熵 <6.5 的条带占比(分节统计);
4. **交互边界**:允许被动等待 + 窗口激活/前台化等 Win32 消息级操作;
   ❌ 禁止向控件注入内容、❌ 禁止凭据尝试、❌ 禁止任何目标内存写入;
5. **dump 决策规则**:若末次 B 相 `.rdata2` 覆盖率 ≥60% 且锚点页均 <6.5 →
   同轮内执行 dump + loader smoke N≥3;否则如实记录覆盖率后停止(数据即交付);
6. 报告 `docs/GTO_H5_LIVE3_R1_REPORT.md`:时间线 + 各时点覆盖率表 + 空间分布图数据 +
   非声明段;记账 used=1/2。

## 三、Round 2(条件):最优点补测或 dump

仅当 Round 1 数据显示覆盖率随时间仍在上升、或 R1 因交互不足未达稳态时启动;

归因指向"可再提升覆盖"时使用。
