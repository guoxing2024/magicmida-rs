## 三、调度循环初步（取指→译码→分派）

### 3.1 主循环（两源一致，独立复算转移计数）

```
0x90176 ──342,220──► 0x8f051 (取指) ──216,150──► 0x8f099 (译码)
   ▲                                                  │ 238,672
   │                                                  ▼
   │  ← 144,114 / 94,577 / 90,037         0x8f374 (分派)
   │  (0x91529/0x91521/0x91512)                 │ 144,112
   │                                             ▼
   └────────────────────────────────────── 0x9150d (handler 选择)
```

- **0x90176** = 分发中枢（24 出边，回边 342,220→0x8f051）
- **0x8f051** = 取指入口（`lea rbx,[rip+0xf5e5e]` 定位指令表基址候选 0x184eb6）
- **0x8f099** = 译码分支：`lea ecx,[rsp+0x40]; call [rip+0x9e825]`（槽 0x12d8c8 → **0x7ffdfe0702d0 运行时堆指针**）——**取指/译码核心是运行时动态生成代码**（变形代码，E15 发现三印证）
- **0x8f374** = 分派器（VM 状态写 + 间接跳转 handler 表）
- **0x9150d** = handler 选择（cmp edx,1：整型 r8b=0x11 / 浮点 r8b=0x21+cvtdq2pd）

### 3.2 重要复核项（ISA_SPEC_V0 的"主译码器 0x8c4c0"）

- **0x8c000-0x8cfff 全页两源 trace exec=0**；0x8c4c0、0x8f0bb（`call 0x8c4c0` 所在）exec=0
- ISA_SPEC_V0 声称"0x8f099→call 0x8c4c0，216K+ 次（trace 实证）" **与实测不符**：
  - 0x8f099 实际是**间接 call**（槽 0x12d8c8→运行时指针），非直接 call 0x8c4c0
  - 0x8c4c0 静态存在且表A/表B 内容与 dump 一致，但**本批 trace 覆盖路径中从未执行**
- **判定**：0x8c4c0 可能是另一执行路径（未激活分支）或 ISA_SPEC 的"trace 实证"标注有误。
  不否定其静态内容，但**必须修正"trace 实证 216K+"表述**，并在 ISA v1 中注明证据等级。
  → 已列入 Phase 1 中段复核清单（不影响本批调度主链结论——主链由 0x8f099/0x8f374/0x9150d 实测转移支撑）。

## 五、门 1 前置分析（能否抽 VM 字节码做人工推演验证）

### 资产可用性

| 要件 | 状态 |
|---|---|
| ISA 静态自洽（0x8c4c0 表A/表B + 12 handler + 参数解码器 0x1073e0） | ✅ 已具（但见复核项：证据等级需修正） |
| 已执行函数的 VM 字节码抽取 | ⚠️ **受阻**：指令表候选 0x184eb6 在 dump 中**全零未物化**；0x8f099 取指核心为**运行时动态代码**（0x12d8c8→堆指针），静态 dump 不含；表基址依赖 rbp 运行时值，trace 无寄存器快照 |
| 推演 vs trace 对拍 | ⚠️ 依赖上述字节码 + 运行时状态，当前离线资产**不可完整闭环** |

### 结论
**门 1 在当前离线资产下无法完整通过，但非死局**——静态 ISA 骨架已就绪，缺口集中在"字节码缓冲区定位 + 运行时寄存器观测"：
1. **离线可推进**：ISA v1 静态自洽补全（12 handler 数据流、0x8c000 区归属复核）
2. **需 owner 决策**（二选一）：
   - A. 允许一次**定向 dump 格**（GVM 1/8）捕获 rbp/rbx 运行时值与指令表内容（高置信、实弹）
   - B. 门 1 降级口径：以"调度区主循环实测语义（0x8f051/0x8f099/0x8f374/0x9150d）"为 ISA 描述对象，
     容忍"ISA=解释器协议描述，非逐字节码"的降级（纯静态可能永远无法闭合——取指是运行时变形代码）
3. **正式门 1 执行点**：抽 0x3d610（原生路径）/0x926d1（VM→原生边界）/0x925c8（调用 handler）三函数对拍
