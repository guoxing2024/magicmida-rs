## ② 战役架构（三阶段，门禁制）

### Phase 1 — `0x3d610` 测绘（预计 2-4 周，账本 GVM 0/8）

| 任务 | 交付 |
|---|---|
| 调度循环语义还原 | 调度器函数族的取指/译码/分派机制（**跨 trace 源合并**：E15_align + gto_tr_t2 D 系列） |
| Handler 清单 | 全部 VM handler 盘点 + 语义分类（算术/内存/分支/调用/API） |
| 字节码格式 | 操作码编码、操作数布局、立即数与加密方案 |
| 数据面解密时刻表 | 运行时解密触发点与算法（`0x11ba34` 启动解密器已测绘，扩展到全量） |

**门 1（go/no-go）**: 能否产出**自洽的 ISA 规格书**——随机抽 3 个已执行函数的 VM 字节码，
人工按 ISA 规格推演出的行为与 trace 实测一致。**过不了 = B1 判死，回退 B2/B3，已耗账目封存。**

### Phase 2 — Lifter 研制（预计 3-6 周）

VM 字节码 → IR → 可编译 C/原生码的自动翻译管线。
**门 2**: 端到端 devirt 一个完整函数（靶子 `0x3d610`，测绘最全），
重建的原生函数行为与 VM 执行逐语义等价（trace 对拍）。

### Phase 3 — 整机反虚拟化 + 原生重建（预计 4-8 周）

全量函数 devirt → 原生 EXE 重组（复用 T3-5R 的 **IAT 名表基建**；EP 侧按本战役 devirt 产出重建，
不沿用 T3-5R 的 G-BOOT 路径）→ S1-S4 全量验收（熊熊标准）。
