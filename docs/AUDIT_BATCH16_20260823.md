## 3. WO-1601 审计

### 3.1 已确认修复

`from_blob_bytes` 现在在 `Vec::with_capacity` 前检查固定字段、count 上限和 checked candidate region；`parse_section` 在分配/切片前检查固定 stride、状态、count 上限和 checked payload region。hostile 测试覆盖了 count、stride、截断和超大 section，方向正确。

### 3.2 P1-1601-1 — encode_section 仍能输出非法 wire record

文件：`crates/antidebug-runtime/src/walker_protocol.rs:1185-1277`。

`encode_section` 自称“never emit a section that violates the frozen wire contract”，但入口没有调用完整 header/identity/result validation：

- 可传入 `header.results_off < MIN_SECTION_HEADER_BYTES` 或未对齐值；`result_count=0` 时 `end` 检查仍可通过；
- 可传入错误 magic/version/stride/status/completed flag；
- 不校验 identity magic/version/CRC/nonce/session/target PID；
- 不校验 `ProbeResultV2` 的 canonical VA、flags、classification、span、reserved。

结果是 API 可以生成随后必被 `validate_section` 拒收的 section，和函数注释/验收合同冲突。必须明确它是 validated constructor，或改为完整拒收。

### 3.3 P1-1601-2 — params 总长度上限仍非 decode 合同

`from_blob_bytes` 检查 count 与候选区，但没有明确拒收 `blob_total_bytes > MAX_BLOB_BYTES`，也没有要求 `blob_total_bytes == header + candidate_count*stride`；它允许带任意 trailing bytes 的超长 blob 返回成功，只有后续 `WalkerParamsV2::validate` 才拒收。

如果 target 先按 `from_blob_bytes` 结果进入后续逻辑，协议层会先接受不符合 frozen layout 的 blob。decode API 需要在返回成功前执行完整 structural validation，或者明确所有调用者必须先 validate 并以类型隔离未验证对象。

## 4. WO-1602 P0 阻断

### P0-1602-1 — SEH 收口机制仍未冻结、且提出了错误替代项

文件：`docs/WO-1301A-IMPL-walker-execute-design.md:296-313,333-343`。

文本同时列出：

- `__try/__except` C shim；
- “等价 FFI 边界”；
- `RtlInstallFunctionTableCallback + 自定义 SEH 展开”；
- “最小内联汇编帧”；
- 伪结构内仍保留 `unimplemented!()`。

这些不是同一机制。`RtlInstallFunctionTableCallback` 是 unwind/function-table 回调能力，不等于自动创建一个能捕获该 probe fault 的 SEH frame。当前没有冻结 C shim 的 ABI、异常过滤器、handler continuation、x64 unwind metadata、DLL 生命周期和失败语义。

因此 P0-A 尚未关闭，不能派发 Windows VEH/SEH 实现。

### P0-1602-2 — probe_span 合同与实际读取宽度矛盾

协议允许 `probe_span ∈ [1,64]`，设计文档 `:230-247` 的 probe 原语却固定执行两次 8-byte load，总是读取 16 bytes：

- `probe_span < 16` 时，协议只按 span 做 page-cross 检查，但实际第二次 load 可能跨页并触发额外 fault；
- `probe_span > 16` 时，实际只读取 16 bytes，结果却可能宣称读取更大的 span；
- `ProbeResultV2` 只有 16-byte observed 缓冲区，也无法承载 17–64 字节完整探针数据。

必须把 span 固定为 16，或设计真正按 span 读取并定义输出/跨页/结果合同。当前不能作为 Walker ABI 输入。

### P1-1602-3 — 未知异常 TLS 生命周期不完整

VEH 写入 `TLS.unknown_code` 后，如果保护器处理该未知异常并 `CONTINUE_EXECUTION`，文档允许 walker 继续；但没有定义何时清零该 TLS、如何避免下一候选继承旧 unknown code、如何验证保护器处理的是同一 fault。应按候选清理并绑定 exception record/RIP，否则状态污染。

## 6. WO-1605 P0/P1 阻断

### P0-1605-1 — 独立 digest slot 没有 ABI 可达路径

文件：`docs/WO-1505-loader-abi-matrix.md:122-145`，对照真实 `crates/antidebug-runtime/src/exports.rs:89-190`。

文档最终冻结方案 B：controller 在 target 内分配独立 digest slot，initialize 读取并回显。但真实 `MidaAntidebugInitialize` 只有一个 `*const MidaInitParams` 参数，且当前 `MidaInitParams` 没有 digest slot 地址/长度字段。`out_runtime_sha256` 是输出缓冲，不是输入地址。

因此 runtime 没有任何方式知道该“独立 slot”在哪里。方案 B 不是 ABI 合同，只是未接线的内存分配描述。

必须在设计层二选一：

- 扩展并版本化 `MidaInitParams`，带 target-local digest pointer/offset + length；或
- 不让 runtime 回显 digest，完全由 controller 在 acceptance 侧用外部 authority record 绑定，并明确这是弱化证据模式；或
- 设计有真实固定地址/全局握手协议的输入通道，并给出 ownership/生命周期/校验。

当前不能派发 loader/runtime 实现。
