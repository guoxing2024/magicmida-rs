## 3. P0 审计发现

### P0-1802-1 — Rust/C TLS call-token 没有可落地的共享 ABI

证据：[WO-1702-seh-probe-shim-contract.md](WO-1702-seh-probe-shim-contract.md) §2.1-2.3、§4.3。

文档的 C 头文件只导出 `mida_probe_read` 和 `mida_probe_call_token_layout()`。后者返回 `va=NULL, seq=0` 的静态 layout anchor，并不返回当前探针的 TLS。与此同时，Rust fixture 只写了伪代码 `TLS.call_token = (va, seq)`，没有定义：

- TLS 存储由 C 还是 Rust 所有；
- C filter 如何无函数调用地读取 Rust 写入的当前 token；
- `active`、probe-thread identity 与 call-token 的跨 ABI 表示；
- `repr(C)` 的 size/alignment/offset 静态断言及 x64 TLS 访问方式；
- begin/set、clear、异常返回、嵌套/重入和 stale-token 的并发时序。

因此“线程 + active + `ExceptionInformation[1]` 匹配”目前只是判定公式，不是可实现且可审查的 ABI 合同。该缺口阻断 SEH 实现派发。

### P0-1802-2 — Windows fault attribution 仍未形成行为证据

文档把 `ExceptionInformation[1]` 作为 AV/guard 的 faulting address，并假定两条 volatile 8-byte load 分别产生 `va` 与 `va+8`。这可以作为候选合同，但仓库没有 `probe_shim.c`、MSVC 编译产物、SEH filter、VEH 注册或 Windows 单测，无法证明：

- guard violation 在目标 Windows 版本上提供所需的 exception information；
- 编译器实际生成的 load 没被重排/合并成不同 fault primitive；
- filter、VEH 和保护器对同一异常的顺序及 `CONTINUE_SEARCH/EXECUTION` 行为；
- `out16` 或 `status_slot` 故障时不会进入未处理异常路径。

该项不是要求当前立即实弹，而是要求先把 ABI/离线合同补齐；Windows 行为仍需未来独立授权和实测，不能用 fixture 代替。

### P0-1803-1 — V2 digest ABI 尚未与真实 loader/runtime 闭环

对照真实源码：

- [exports.rs](../crates/antidebug-runtime/src/exports.rs:87) 只有 `MidaInitParams` 与 `MidaAntidebugInitialize`，没有 `MidaInitParamsV2`/`MidaAntidebugInitializeV2`；
- [exports.rs](../crates/antidebug-runtime/src/exports.rs:237) 仍写入 `adr4-foundation-unbound`；
- [runtime_loader.rs](../crates/cli/src/unpacker/runtime_loader.rs:533) 的 `MidaExports` 仍为 3 字段；
- [runtime_loader.rs](../crates/cli/src/unpacker/runtime_loader.rs:1451) wanted 列表仍只有 3 项，解析结果也仍只构造 3 字段；
- [runtime_loader.rs](../crates/cli/src/unpacker/runtime_loader.rs:1094) 之后仍只构造 v1 0x30 params，并调用现有 6 参数 initialize。

因此文档中的 0x48 V2 layout、V2 export、5-item wanted list、digest echo 和 controller equality 都是待实现设计，不是已关闭的 ABI。

### P0-1803-2 — target-local digest pointer 的安全读取与 fallback 门禁未定义到可验证级别

设计要求 runtime 读取 target-local `64 hex + NUL`，但当前 runtime 的 [`read_cstr`](../crates/antidebug-runtime/src/exports.rs:488) 是无进程内存边界证明的裸指针扫描；它先解引用再检查上限，并且现有初始化对 profile 指针也依赖 caller contract。V2 没有给出可执行的 target memory validation/SEH 方案、65-byte 可读性检查合同、非法指针错误码路径或测试矩阵。

此外，“无 digest 需求时 v1 fallback”没有被定义成可检查的唯一条件。必须明确 Walker、v2 attestation、digest-bound acceptance 任一启用时，v1 路径是否一律拒收；否则存在误落入 `adr4-foundation-unbound` 的无绑定路径。
