## 3. P0-1901 审计发现：TLS 合同仍自相矛盾

### 3.1 C owner 与 Rust 伪代码冲突

`docs/WO-1702-seh-probe-shim-contract.md` §4.4 已写明 TLS 唯一 owner 为 C shim，Rust 只能调用 `mida_probe_tls_begin/clear/snapshot`。但同步后的 `docs/WO-1301A-IMPL-walker-execute-design.md` §3.3.2 仍出现：

```text
PROBE_TLS.with(...)
PROBE_TLS.with(|t| t.MidaProbeTls.token_va)
PROBE_TLS.with(|t| t.guard_seen / av_seen / unknown_code)
```

这不是显示层问题，而是两份权威设计对“状态存储 owner”和“VEH 读取路径”给出不同 ABI。实现 worker 无法照抄而不自行裁决，P0 不能关闭。

### 3.2 TLS 结构没有承载正文声称的异常标记

`docs/fixtures/WO-1901-probe-tls-fixture.h` 的 `MidaProbeTls` 字段只有：

```text
magic / active / seq / reserved / token_va
```

但 §5.1/§5.2 仍要求同一 TLS 状态保存 `guard_seen`、`av_seen`、`unknown_code`，并要求 VEH 写入、Rust 主路径读取。没有定义这些字段是在另一份 C TLS、共享状态槽、还是 controller-owned memory；也没有 accessor 的 snapshot 返回结构覆盖这些字段。当前 fixture 只验证 `AttrInput` 分类，不证明真实状态存储闭环。

### 3.3 seq 归属规则没有形成闭环

正文声称 `seq` 与调用方期望不符时 abort，但 `ExceptionRecord`/filter 输入没有 expected sequence，`mida_attr_classify` fixture 也没有 `seq` 或 expected_seq 字段。仅在主路径 snapshot 后比较，无法区分“当前 token 正确但异常来自旧 fault”与“当前调用异常”。必须明确 seq 的用途、写入者、比较者和异常时序；不能只在表格中写“seq mismatch → abort”。

### 3.4 仍是 design-only

仓库没有 `probe_shim.c`、build.rs 的 cc 编译门、MSVC 产物、VEH 注册实现或 Windows 行为测试。TLS fixture 只能证明布局/纯逻辑假设，不能证明 compiler TLS、SEH filter 和保护器链行为。

## 4. P0-1902 审计发现：V2 pointer safety 缺少可证明的 blob 边界

### 4.1 真实 ABI 没有 blob size/base

文档冻结的 V2 入口是：

```text
MidaAntidebugInitializeV2(const MidaInitParamsV2* params, ...)
```

现有 v1 入口也只有 `const MidaInitParams* params`，真实 loader 在 `runtime_loader.rs:1165-1173` 通过单个 `remote_params` 指针调用 thunk。V2 结构的 0x48 layout 只有 v1 字段、magic、digest pointer、digest length，没有 `blob_base`/`blob_size`/`header_bytes`。

然而 WO-1902 §5.3b 要求 runtime 在**解引用前**检查：

```text
blob_base <= pointer < blob_base + blob_size
```

入口没有获得 blob size，结构也没有该字段，runtime 无法执行这条规则。把“controller 已知 VirtualAllocEx 分配范围”写进文档，不能让 target runtime 自动知道该范围。必须新增冻结的 envelope/size 通道，或改为所有 target-local pointer 使用可验证的 self-relative offset；否则 pointer safety 只是声明。

### 4.2 无 size/version 导致短 blob和未知版本判定不安全

V2 通过 offset `0x30` magic 区分版本，但一个只分配/写入 v1 `0x30` 字节的 caller 仍可能把 `params` 指向长度不足的内存。入口没有 `size` 参数，不能在读取 magic 前证明至少有 0x38 bytes；也没有独立 version/size 字段可拒收未知扩展。独立 V2 export 解决了 v1 不读取尾部的问题，但没有完成 V2 自身的长度/版本安全协商。

### 4.3 其余设计项属于待实现，不是关闭证据

5 项 wanted、MidaExports 五字段、V2 thunk 对位、fallback 三条件均已写入文档，但真实 `exports.rs` 与 `runtime_loader.rs` 仍是 v1/3-export/placeholder digest。WO-1904 已正确记录这些项目未实现，因此 WO-1902 不能标记 P0 closed。
