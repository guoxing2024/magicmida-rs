## 2. P0 详细问题

### 2.1 IMP-01 与冻结 schema 不一致

权威合同：

```text
D:\Claude project\magicmida-rs\docs\WO-1503-attestation-v2-schema.md
D:\Claude project\magicmida-rs\docs\WO-1705-schema-implementation-readiness.md
```

当前 `crates/antidebug-runtime/src/attestation.rs` 的新增类型与合同不对位：

- 缺少 `RuntimeAttestationV2` 顶层类型；
- 缺少 `schema_version: u16 == 2`；
- 缺少 v1/v2 tagged dispatch；
- `WalkerAttestation` 缺少 `target_image_sha256`、`runtime_module_sha256`、`walker_export_rva`、`walker_entry_va`、`rounds`、`probe_summary`、`orphaned_resources`、`canonical_encoding`、顶层 `record_digest` 等冻结字段；
- `RoundLedger` 被改造成 session/profile/rounds/orphans 结构，缺少冻结的 `round_index`、`entry_ts`、`exit_ts`、`wall_budget_ms`、`wall_spent_ms`、`candidates_probed`、`abort_state`、`auto_retry`、`next_round_authorized`；
- `ProbeSummary` 缺少 `candidates_total`、`type_a_count`、`type_b_count`、`type_c_count`、`av_count`、`guard_count`、`retry_count`、`total_latency_us`；
- `Orphan` 缺少 `kind`、`target_pid`、`blob_base_va`、`section_name`、时间字段、封闭 `state`、`reclaim_note` 和 `unconfirmed` 约束。

精确位置：

```text
crates/antidebug-runtime/src/attestation.rs:473-704
```

此外：

- `RoundLedger::validate()` 只检查递增，不限制 round 为 `{1,2}`，不检查预算、abort_state、auto_retry；
- `prev + 1` 位于 `:590`，未使用 checked arithmetic，`u64::MAX` hostile round sequence 存在溢出/调试 panic 风险；
- `WalkerAttestation::validate()` 未验证 `ledger_digest` 与实际 ledger 的绑定，也未验证 runtime digest 格式、模块/RVA/entry VA 关系。

### 2.2 json-c14n 实现不满足冻结算法

```text
crates/antidebug-runtime/src/attestation.rs:428-458、548-560、603-611
```

当前 `json_c14n()` 只做递归 key sort + `serde_json::to_string`。冻结合同明确要求：

- UTF-8 字节序键排序；
- 非 ASCII 原样 UTF-8；
- 整数/有限 double 规则；
- `-0` 规范化；
- NaN/Infinity 拒收；
- bool/null 固定编码；
- 顶层必须 object；
- 非法 UTF-8/代理对拒收；
- v2 digest 不得混用普通 `serde_json::to_string`。

当前实现没有完整执行这些拒收与数字规范规则，固定 vectors 也没有覆盖冻结文档要求的全部 vectors。

### 2.3 IMP-03 `digest_len` 与 ABI 冻结冲突

```text
crates/cli/src/unpacker/runtime_loader.rs:2398-2420
```

当前：

```rust
pub const V2_DIGEST_LEN: u64 = 65;
```

但权威 ABI 合同要求：

```text
digest_len == 64
```

65 是 `64 个 hex 字符 + 1 个 NUL` 的**存储区域长度**，不是 `digest_len` 字段值。合同原文见：

```text
D:\Claude project\magicmida-rs\docs\WO-1505-loader-abi-matrix.md:261,277,324-329
```

当前 `build()` 把字段写成 65，测试还明确断言 65，属于生产 ABI 级错误。

同时 `parse_offsets()`（`:2457-2490`）没有完整验证：

- `digest_len == 64`；
- digest 65-byte NUL 有界扫描；
- profile/profile_digest NUL 有界扫描；
- offsets 至少位于 header 之后；
- `expected_surfaces_off + expected_hooks*8` checked bounds；
- surface entry canonical/provenance/NUL 约束；
- digest region checked bounds；
- strict extension 等长合同；
- reserved/header trust boundary。

因此不能称 V2ParamsBlob 已 fail-closed 完成。

### 2.4 IMP-04 存在可构造 false PASS

```text

```

`ImplementationFacts` 没有：

- live authorization 状态；



这与项目硬门“无 LIVE-4/Windows live 不得 acceptance allowed”冲突。测试 `fully_implemented_and_dispatched_passes` 正在固化这个过宽的 PASS 条件。
