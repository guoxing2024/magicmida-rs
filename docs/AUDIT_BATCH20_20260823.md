## 3. P0-2001：TLS ABI 仍不一致

### 3.1 C 0x20 与 Rust 0x18 冲突

C 合同和 fixture 当前定义：

```text
magic +0x00
active +0x04
seq +0x08
flags +0x0C
token_va +0x10
unknown_code +0x18
size 0x20
```

但 `docs/WO-1702-seh-probe-shim-contract.md` §2.3 Rust FFI 仍是：

```text
magic / active / seq / reserved / token_va
```

没有 `flags`、`unknown_code`，仍是旧 0x18 解释。Rust 侧还只声明 `begin/clear/snapshot`，未同步 `mida_probe_tls_mark`。因此“C/Rust/fixture 全文一致”不成立。

### 3.2 stale 检查不可达且顺序未冻结

fixture 先执行 `active == 0 -> ATTR_ABORT`，随后才执行 `active == 0 && flags != 0`，后者永远不可达。正文同时写 begin 会清零 flags/unknown_code，但没有要求清零前先拒收 stale 状态。若先清零，会静默丢弃上一候选残留证据，不满足 fail-closed。

### 3.3 design-only 边界

仓库仍没有 `probe_shim.c`、build.rs cc 编译门、Rust FFI 实现、VEH 注册、MSVC 产物或 Windows 行为测试。修正文档后仍只能是实现前合同。

## 4. P0-2002：V2 envelope 尚未单一化

### 4.1 同一文档存在两套冲突布局

`docs/WO-1505-loader-abi-matrix.md` 前部新增了 self-relative V2：

```text
profile_id_off / profile_digest_off / expected_surfaces_off / digest_off
```

但后部仍保留旧的“v1 字段 + `expected_runtime_sha256` 绝对指针 + len”布局、golden bytes 和 static_assert。旧 fixture `WO-1902-initparams-layout-fixture.h` 也继续定义绝对指针 V2。没有明确废弃/删除时，worker 无法判断唯一权威 ABI。

### 4.2 fixture 覆盖不完整

`WO-2002-v2-envelope-fixture.h` 只检查 digest 与 surface array 外壳，未检查：

- `profile_id_off`、`profile_digest_off` 的边界；
- profile 字符串 NUL 终止；
- surface array 每个 entry 的 canonical/nonzero/provenance；
- `expected_hooks * 8` 的 checked multiplication；
- surface string 本体是否落在同一 envelope。

此外 fixture 直接使用 `in.blob + digest_off`，没有冻结 `blob == params` 或同 allocation 证明。

### 4.3 header trust boundary 未闭合

入口检查 `params_bytes >= 0x48` 后就读取 `params->magic_v2`。但调用方提供的长度值不证明 `params` 前 0x48 字节已提交且可读，也不证明 `params` 与 `params_bytes` 属于同一 allocation。合同必须明确 controller provenance、target-local allocation identity、header fault 的 fail-closed 处理与信任边界。

### 4.4 version/extension 语义矛盾

文档既要求未知版本拒收，又允许 magic 匹配且 `params_bytes > 0x48` 的未知尾部。必须选择：严格拒绝未知扩展，或定义兼容扩展规则与 `header_bytes/schema_version`；不能两者并存。
