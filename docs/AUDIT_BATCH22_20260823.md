## 4. P0-2202：V2/7-arg ABI 仍未闭合

### 4.1 7-arg thunk 的“13 字节”合同错误

`docs/WO-1505-loader-abi-matrix.md` §5.3c 将 `THUNK_CODE_7ARG` 标为 **13 字节**，但同时列出：

- 4 个寄存器参数 load；
- 3 个额外参数 load；
- 3 个栈槽 store；
- 1 个间接 call；
- ret。

按文档自身指令序列计算，长度约为 **46 字节**，不可能是 13 字节。更严重的是：

```text
mov r11, rcx       ; 文档写 48 8B CB
call [r11]         ; 文档写 FF 53 00
```

这些注释不是对应 `mov r11,rcx` 与 `call [r11]` 的可靠 x64 machine-code encoding；现有 loader 的 6-arg thunk 也没有 `THUNK_CODE_7ARG` 或 `ThunkArgs7` 实现。实现 worker 无法“原样落地”该合同，P0 必须退回。

### 4.2 surface provenance 的加法未闭合

当前 fixture 在检查 surface entry 时使用：

```c
sva < expected_blob_base_va ||
sva >= expected_blob_base_va + params_bytes
```

`expected_blob_base_va + params_bytes` 没有 `mida_checked_add`，当 base 接近 `UINT64_MAX` 时会回绕，可能错误接受越界 VA。文档要求 checked arithmetic，但 fixture 没有实现该证明。必须增加 base canonical、base-plus-size overflow、entry canonical/nonzero 和 string scan 的完整拒收测试。

### 4.3 仍是 design-only

当前真实源码仍然没有：

```text
MidaAntidebugInitializeV2
THUNK_CODE_7ARG
ThunkArgs7
WalkerExecute
```

因此即使修正文档，也只能通过 design gate，不能直接进入 runtime 实现或 LIVE-4。
