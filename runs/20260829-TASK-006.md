## 四、崩溃根因分析（cdb + 静态，字节级）

**cdb 捕获（2 次独立运行均同址崩溃）：**

```

  00000000`005fff90 00000000`00000000 : ntdll!RtlUserThreadStart+0x2c
```

**静态定位（本报告核心证据链）：**

1. `0x1681d1` 落在 **.pdata 节**（异常目录，va 0x168000 vs 0xbbe0，chars 0x40000040 = 只读数据，**不可执行**）。该地址字节是 `e2 10`，是 .pdata 中 `RUNTIME_FUNCTION` 结构 `UnwindInfoRVA` 字段（0x10e2bc）小端字节的第 2-3 字节，恰好解码为 `loop` 指令。
2. 执行流从 `.text` 到达 `0x1681d1` 的路径：`0xde785` 处 `FF 15 45 50 03 00` = `call qword ptr [rip+0x35045]` → `call [0x1137d0]`。
3. **IAT/数据槽 `0x1137d0` 的固化值 = `0x1401681d1`** = 映像基址 0x140000000 + RVA 0x1681d1（.pdata 中间）。
4. 对照：上一 worker 的同会话**未修复**宿主 `rev2_unpacked.exe`（`698b1172`）同一槽 = `0x1762f4`（hint/name RVA，loader 可解析）→ 该宿主能活（timeout 12s 未退出，见下）。
5. 即：dump 重建流程在 `0x1137d0` 槽把**运行时快照的绝对地址**固化，其中一个指向**映像自身 .pdata 数据区**（本不是函数），导致启动初始化期 `call [0x1137d0]` 跳进 NX 数据 → AV。

**同型性对照（与本工单背景 T0.5 的关系）：**

| 固化点 | 旧 rev2（T0.5，`36043cb4`） | new fixed（本会话，`bb5ee568`） |
|---|---|---|
| .bss RVA 0x112c10 | `0x7ffeeb426390`（**旧**会话 ntdll+0x106390） | `0x7ffa953a6390`（**本**会话 ntdll+0x106390） |
| 含义 | 跨 ASLR 重启必崩（T0.5 实锤） | **跨 ASLR 重启必崩（会话绑定残留未清）** |
| 影响 | 启动即崩（重启后） | 当前会话不崩（地址有效），重启后必崩 |

**两个独立缺陷：**
- **缺陷 A（首要阻塞，与 ASLR 无关）**：IAT/数据槽 `0x1137d0` 固化 `0x1401681d1` → 指向自身 .pdata → **当前会话即启动 AV**。这是 dump 重建缺陷（重建时把运行时指针固化进只读节），**不是 /session-clean 能修的**：`0x1401681d1` 是映像内部地址，不在任何会话模块表区间内，`/session-clean` 的判定语义（按 `session_modules` 区间清洗）无法识别、不会清洗。
- **缺陷 B（会话绑定，工单要根治的对象）**：.bss `0x112c10` 固化**本会话** ntdll 绝对地址 `0x7ffa953a6390`。当前会话有效（不崩），但**跨 ASLR 重启必崩**——T0.5 旧宿主同型问题未消除。

**结论：上一 worker 的 new fixed 宿主既"当前会话不可用"（缺陷 A），也"跨会话不可移植"（缺陷 B）。TASK-006 两个核心目标均未达成。** [已验证]
