## 二、修复方案与理由（组合：兜底清零 + fail-closed）

工单给了两个方向，本修复**两者组合**，理由如下：

### A. 兜底清零（primary safety net）— `dump_process.rs`
- 新增纯函数 `zero_fill_iat_region`（`dump_process.rs:3216-3228`）：在 `create_import_section` 之前，把 `[original_iat_rva, +iat_span)` 整段清零（span 取 `opts.iat_location` 或 `iat_report.requested_bytes`，clamp 到 dump_buf）。
- `create_import_section` 随后把重建 thunk 的值写回各自槽位；未被重建覆盖的槽保持 0（honest hole / loader 运行终止符）。
- **理由**：与 `/session-clean` 对 unmappable 指针的清零语义一致（`sidecar_consumer.rs:265-267`：无法可靠映射的旧会话指针清零，让加载期重解析）。零值不会被 `fix_hardcoded_addresses` 重写，也不会被 loader 当作 hint/name RVA 或 NX 目标。这是"兜底"，保证**任何**重建不完整路径（stub 回退 / graded 洞 / 无 builder）都不再把运行时指针留在只读节。

### B. fail-closed（缺陷捕获，防"带 blocker 还打 [GOOD]"）— `iat_partial_accept.rs` + `iat_gap_retarget.rs` + `dump_process.rs`
- `iat_partial_accept.rs:400-425` 新增 `unresolvable_slot_rvas(&IatRecoveryReport) -> HashSet<u32>`：收集所有非 `Resolved`/`ZeroTerminator` 槽的 RVA（离线策略腿）。
- `iat_gap_retarget.rs:31-71` 新增 `call_sites_targeting_slots(&PeHeader, &[u8], &HashSet<u32>) -> Vec<(u32,u32)>`：扫描可执行节 `FF 15/25` 直接调用点，返回指向目标槽的 `(site_rva, target_rva)`（复用该模块既有的节扫描/定位模式）。
- `dump_process.rs:2843-2877` fail-closed 门：在**所有 in-image 变换之后、写出产物之前**（gap retarget 可能已把部分站点重定向到重建 API，门必须在其后跑），若有直接调用点指向不可解析槽 → `return Err(PeError::Parse("TASK-009 fail-closed: …"))`，产物不写出。
- **理由**：清零兜底能把"未重建槽"变成 honest hole，但如果存在**直接 call 指向该洞**（如 `.text 0xde785 → call [0x1137d0]`），产品一执行该代码就跳零/NX 必崩——清零救不了。此时产物判不合格、dump 以错误退出 → `post_loop` 的 `?` 提前返回，`[GOOD] Candidate written` 不再打印。与工单"存在直接 call 指向它且无法兜底时产物判不合格"完全对应。graded 路径（XX-9-A，≤4 rejected + ≥95%）仍保留：无直接 call 指向洞 → 正常出产物。

**未改动语义**：`/session-clean`、`data_reinit.rs`、`_clippy_baseline`、`ci.yml` 判定逻辑均未动。`iat_gap_retarget.rs` 的既有 `retarget_iat_gap_call_sites` 行为不变（仅新增共享扫描函数）。

3. **fail-closed 门的保守性**：门会在"任一可执行节存在直接 call/jmp 指向任一不可解析槽"时拒绝产物。对 OreansClassic 这类无 wrapper/gap-retarget 的 profile，门是最终防线；对 AhkGtoExperimental，门在 gap retarget 之后运行，已被 retarget 合法改写的站点不会误杀。但"存在直接 call"是保守判据（不区分该代码是否真的在启动路径执行）——宁可 fail-closed 也不出必崩产物，符合工单红线。若将来有样品大量误触发，可加"调用点前的 test eax,eax 模式"等精化（属后续工单）。
4. **graded 路径回归风险**：XX-9-A 的 graded 接受（≤4 rejected + ≥95%）仍有效；若某 rejected 槽恰好有直接 call 指向，会 fail-closed。这是工单要求的行为（存在直接 call 且无法兜底 → 判不合格），不是回归。
5. **`clippy` 输出中的既有 warning 计数**：mida-pe 218 / themida 32 / cli 57 全部为改动前既有；本修复未引入新 lint（已逐条核对三个授权文件无 warning）。`_clippy_baseline` 无需下调。
