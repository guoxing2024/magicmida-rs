## 阻塞点

无。但过程中撞到一个环境级问题并已修复：

**rustc 1.97.1 在本工作区因增量编译缓存 ICE。** 第一次跑格式化后的测试时，
`mida-disasm` 编译触发 `error: the compiler unexpectedly panicked. This is a bug`（compiler flags 里含 `-C incremental=...`）。
删掉 `target/debug/incremental` 并把 `CARGO_INCREMENTAL=0` 固化进 `tools/_enter_msvc_env.cmd` 后一次通过。
之前那次成功的全量测试恰好也设了 `CARGO_INCREMENTAL=0`，所以之前没暴露。已记入 `docs/KNOWN_ISSUES.md` E-5。

1. **那 31 个文件的 fmt 债是从什么时候开始的，我没查。** 我只确认了"HEAD 上就不合规"，没有二分查找是哪个提交引入的。如果想知道 CI fmt 红了多久，需要对历史提交跑 `cargo fmt --check`。
2. **CI 是否真的因此红过，我无法查证。** 本机没有 `gh`，我没有看到任何一次 CI run 的实际结果。"CI fmt job 是红的"是我从"本机 fmt 检查失败 + CI 跑同一条命令"推出来的 **[推断]**，不是 [已验证]。
3. **ICE 的真正触发条件我没有隔离。** 我不知道它是"增量缓存被中断的构建写坏了"还是"这个工作区 + 1.97.1 的稳定复现"。我采取的是回避（关掉增量），不是定位。如果将来有人需要增量编译的速度，这件事需要重新查。
4. 标准 2 我比对的是"与格式化前基线一致"，这能证明格式化没改变行为，**不能**证明这 2801 个测试覆盖了什么。测试覆盖率本身我没评估。
