## 三、实现说明

### 风暴判据（保守、可解释）

- 元组 = `(exception_addr, target_address, exc_type, thread_id)`，与工单要求完全一致。
- **元组变化即清零**（streak 重置为 1），只抓"恒同"环，不误伤正常多样 AV 流（VM 推进时会演化元组）。
- 阈值 = 命名常量 `GARDLESS_AV_STORM_TUPLE_THRESHOLD = 32`，**非魔数**。选值理由（写入代码注释）：
  - 与 CLI 既有 `unrelated_av_storm_threshold` 默认值 32（`crates/core/src/plugin.rs` `PluginCtx::default`）同值，guardless 阶段与 guard 阶段共享同一语义标尺。
  - 实测风暴几何（04:0x 同元组 322 万次、21:1x 20万–300万次）超出该阈值数个数量级，32 与正常 AV 节奏之间有极大裕量，误杀风险低、日志预算有界。

### 中止语义 = fail-closed

- 超阈值 → `decide_av_oep` 返回 `Break`（`oep: state.oep.unwrap_or(0)`，`storm_abort: Some((tuple_text, count))`），与 TASK-009 的 fail-closed 同族（不 dump、不打 [GOOD]）。
- `av_handler.rs` `Break` 分支检查 `storm_abort` → `return Err(anyhow!("guardless constant-AV storm abort (fail-closed): identical AV tuple {tuple} repeated {count} times without guard installed; aborting unpack"))`。
- `mod.rs:2390` 调用点 `?` 直接传播 → `unpack()` 返回 Err → **跳过 `run_post_loop_phases`（dump）与 `[GOOD] Done.`**，日志有界。

### 未改 .text-stable 判定

`mod.rs:1216-1226` 的解密完成判定零改动（`git diff` 验证 0 行触及）。本单只加"环检测中止"，不放宽解密成功条件。

### 设计取舍说明

- **未新增 `AvOepAction` 变体**：工单允许"新增变体或复用现有中止语义"。复用 `Break` + `storm_abort` 状态字段，避免改动 `AvOepAction` enum（会波及 `full_pipeline_replay.rs` 与 `av_handler.rs` 的既有 match，扩大改动面）。`[推断]` 该取舍符合工单授权（"复用现有中止语义"字面允许）。
- **持久化状态放在 mod.rs 循环外局部变量**（非 `loop_state.rs`）：因 `loop_state.rs` 不在授权清单。AV handler 每次调用重建 `AvOepState`，若计数不持久化则风暴检测失效。以 2 个 `&mut` 参数透传，仅触碰授权文件。`[已验证]`
