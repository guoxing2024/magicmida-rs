### 3.1 `git diff 18e0349..291b239` trace 路径审读结论

**trace_imports 自身在 18e0349..291b239 内结构零改动**：
- `trace_imports/mod.rs`：仅 T014 的 slot-scoped 化（lifecycle error 从 fail-fast 改为记 failed 继续走）+ `trace_one_slot_end` 包装 + deepened retry 文案。
- `trace_imports/slot.rs`：仅 T014 的 `trace_one_slot_end`（诊断分类）+ rustfmt。
- **trace 起点逻辑（pending 处理）自 XX-8-A（3b5862b）以来从未变过**：`had_pending_event ? continue_event(trace_thread) : bootstrap`。

**真正的回归源在 18e0349..be28951 的 break 路径（T0.5-R2）**，不在 trace_imports 内：
- `a9aced4`（XX-11 working-line carry-over）引入 `iat_materialize_failclosed_delay`（HW-anchor 失败 → 12s grace window → 在下一个事件上 leave）+ `windows_debugger.rs` 的 DR apply partial tolerance（单线程 ERROR_NOACCESS 跳过）。
- 实弹对比（同一样品、同一 boot 家族）：

| 维度 | XX-11（08-28，成功） | R5/T014（08-30，失败） |
|---|---|---|
| HW anchor arm | `IAT materialize: HW anchor armed at event stop (slot=2, site=0x7ff7f3d11123)` 成功 | `arm deferred HW anchor failed: Windows API error: code 2147943398`（ERROR_NOACCESS） |
| 后续 | anchors never hit 30s → `FreezeAndDump`（wait-timeout 路径，**无 pending**） | 12s grace window → 在 spurious 线程的 `ExitThread` 事件（seq=84）上 `leave_debug_loop`（**pending 未 continue**） |
| trace 起点 | `trace_one_slot: no pending event — bootstrapping via first wait (frozen entry)` | R5：`tracer error (fail-fast): continue_event refused: TID mismatch (provided_tid=<main> pending_tid=<spurious> pending_code=4 seq=84)`；T014：被 slot-scoped 包装吞掉 → 全槽 `tracing completed but no API resolved` |
| 结果 | 74/201 resolved，product_complete=true | 0/74 resolved，fail-closed 拒绝 |

**结论：trace 线程/时机的失败根因 = 断点后遗留的"其它线程 pending 事件"**。post-loop `fix_iat_v3` 用 `main_thread_id` 起 trace，但 debug loop 在 spurious 线程的 `ExitThread` 上 break 且未 continue 该事件，`plan_continue`（`debug_event_lifecycle.rs`）按 TID 校验拒绝 → trace 从未真正单步过（T014 日志无任何 `Suspending spurious thread`/`Giving up trace`/`Trace ran into VM`，µs 级失败）。T014 的 slot-scoped 包装把真实的 TID-mismatch 错误藏成了误导性的 "tracing completed but no API resolved"。[已验证：4 份实弹日志交叉比对]

### 3.2 XX-11 机制链还原（谁单步、单步什么地址、何时停止）

XX-11 的完整机制链（vault `xx11_attempt_20260828-112236/unpack.stdout.txt` + `XX11_REPORT.md`）：
