### 1.2 NtContinue hооk 开关归属 — [已验证]

**结论：`NtContinueHook` 是 InjectorCLI 真实支持的配置键名。**

- 真实二进制 `.rdata` 含 wide 字符串 `NtContinueHook`（rva 0x97830），紧随 `KiUserExceptionDispatcherHook`（0x977d8），与其它 `*Hook` 键名（`NtCloseHook`、`NtCreateThreadExHook` 等）同表 → 它是配置键之一，不是编造。
- HookLibrary 导出 `HookedNtContinue`、`HookedKiUserExceptionDispatcher`（实测 strings）→ 两个 hооk 都有对应实现。

**对工单的如实修正**：工单说"参考 ini 里没有 NtContinueHook 这个键"——**不成立**。两份 vault 参考 ini 都**有** `NtContinueHook=0`：

```
$ grep -n "NtContinueHook" D:/MidaVault/quarantine/20260722/workspace/magicmida-rs/scylla_hide.ini
35:NtContinueHook=0
$ grep -n "NtContinueHook" D:/MidaVault/quarantine/20260722/workspace/reference/Magicmida/scylla_hide.ini
NtContinueHook=0
```

（Magicmida 版本的第 11 行）→ 工单"要确认 NtContinue 被哪个开关带着装"的答案就是 `NtContinueHook`，且参考 ini 已经显式关掉。这不影响任务目标，但必须如实记录。

### 1.3 为什么不能简单"落位"到注入器工作目录 — [已验证]

- ARTIFACT_POLICY 明确禁止活动工作区出现 `scylla_hide.ini`（任何位置，含 gitignore）。
- 实证（1.1b）显示即使把 ini 放到 cwd / exe 目录，`GetPrivateProfileStringW` 相对名也读不到（只搜 Windows 目录）。
- 把 ini 写进 `C:\Windows` 是系统级不可逆副作用，且 `scyllahide.rs`（spawn 逻辑，唯一能改 cwd/传参的地方）在授权范围外。
- → **在授权内，正确做法 = 把 `ini_path` 接上线（去 dead_code）、把配置来源记录到日志与证据 sidecar、并把受控 ini 作为 vault 交付物**；真正让 InjectorCLI 读到受控 ini 需要操作员在实弹前放置到 Windows 目录，或后续授权扩展 packers/themida（写进"我不确定的事"）。
