## 2. 脚本设计（`tools/xx21b_t05_ui_drive_dbg.py`）

### 2.1 与 T017 版的关键差异（观测腿 → 调试端口泵）

1. **宿主创建改调试端口**：`CreateProcessW(..., DEBUG_ONLY_THIS_PROCESS=0x2 | CREATE_UNICODE_ENVIRONMENT=0x400)`，`NO_BYPASS=1` 环境块；`pi.hProcess/hThread` 保留。
2. **调试泵线程（核心）**：独立线程 `pump_loop`，`WaitForDebugEvent(500ms 超时轮询停止标志)` → `_handle_debug_event` → **每个事件立即 `ContinueDebugEvent`**（不消费 = 调试对象冻结，P2b 实证之坑）。
3. **事件处理**：
   - `CREATE_PROCESS_DEBUG_EVENT(3)`：记录 hProcess/hThread/imageBase——**DEBUG_EVENT 原始偏移 24/32/40 读 + 结构体字段双份**（校验一致）；
   - `CREATE_THREAD_DEBUG_EVENT(2)`：记录 hThread，**按 tid 匹配 Run 线程**（`run_thread_ready` 事件）；
   - `EXIT_PROCESS_DEBUG_EVENT(5)`：记录退出码后结束泵；
   - `EXCEPTION_DEBUG_EVENT(1)`：**全部记录**（异常码/地址/首挂起线程 Rip）；`0x80000003` 引导断点 + `0xc000008e` 引导期良性浮点 → `DBG_CONTINUE`，**其它（含真实 AV 0xc0000005）→ `DBG_EXCEPTION_NOT_HANDLED` 不吞**；
   - `LOAD_DLL_DEBUG_EVENT(6)`：计数 + CloseHandle(hFile)；
   - 全部事件边到边落盘 ndjson（提前退出也留证据）。
4. **RIP 采样**：对 Run 线程的 hThread（**来自 CREATE_THREAD 调试事件，不用 OpenThread**——P-11 外部观测族垫零）`SuspendThread + GetThreadContext(CONTEXT_CONTROL_AMD64=0x100001，引擎同款 fast-path) + ResumeThread`；owner 归属 = `enum_modules()` + MZ 双核。
5. **保留 T017 全部机制**：sha256 fail-closed / FindWindowW 窗口发现（EnumWindows 回调不可用 → 已知类名回退）/ GUI 存活观测（IsHungAppWindow / WM_NULL，SendMessageTimeoutW 防挂死）/ 防火墙现状核实（只读）/ NO_BYPASS=1。

### 2.2 两个实测修正（有证据，进报告）

- **[T018-实测] Windows 调试会话线程绑定**：`WaitForDebugEvent` 必须在 `CreateProcessW(DEBUG_ONLY_THIS_PROCESS)` 的**同一线程**调用；跨线程 → `err=6 ERROR_INVALID_HANDLE`、0 事件。修复：宿主创建移入泵线程（probe 3/4 对照，见 §5.2）。
- **[T018-实测偏差，票面"其它 → DBG_EXCEPTION_NOT_HANDLED"的细化]**：`0xc000008e`（STATUS_FLOAT_MULTIPLE_FAULTS）是壳 VM 初始化期良性首机会异常（非调试下宿主自身 SEH 静默处理、宿主正常引导）；调试附加下若按 NOT_HANDLED 路由 → 壳 SEH 弹出 **WinLicense 反调试对话框**并干净退出 → 三态判定不可能。策略：`0x80000003` + `0xc000008e` → DBG_CONTINUE（被动观测），**其它一切 EXCEPTION → NOT_HANDLED 不吞**。AV 三态判据 = EXCEPTION 事件记录（地址/码/Rip）与进程退出码——与 Continue 状态无关，证据链完整。
