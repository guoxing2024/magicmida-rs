## 背景（D-038 定案）

- 候选 core（3650ea6c）是 08-29 会话的 raw 内存 dump 重建品，携带该会话绝对指针。T019 实弹实证：宿主初始化消费其中陈旧 ntdll 指针（`thread_rax = thread_rip = 0x7ffeeb426390` = 旧 ntdll 0x7ffeeb320000+0x106390）→ 取指 AV → 死于 core.dll 加载完成前。宿主 a852880a 无辜（旧值 0 命中；`.bss 0x112c10` = 当前会话 ntdll 0x7ffd37ae0000+0x106390）。
- 已知确定性事实：旧值在候选内 **≥2 处**（首处文件偏移 0x13f810）；候选加载时**会被重定位**（T019 实测实际基址 0x7ffd36310000 ≠ 首选 0x7ffe1da10000）——补丁必须区分"重定位覆盖的槽"（loader 会在加载时再加 delta，直接补当前值会被二次偏移破坏）与"裸数据槽"（直接补当前值即可）。
- T019 报告与本单的共同前提：候选 `.text` 明文、导出完好（Run@0x1c120 / GetAppVersion@0xbb30）、C-8 不适用——清洗只动**数据指针**，不碰代码与结构。

## 任务

### 1. Phase 1 — 陈旧指针普查（扫描 + 分类，不改文件）

新脚本 `tools/xx21b_core_session_cleanse.py`（纯标准库），对候选**副本**扫描：
- 全文件 8 字节对齐 + 非对齐扫描所有"看似指针"的 8 字节值（`0x0000` 开头高 16 位为 0、高位落在 `0x7ff...` 用户态系统区间）；
- 分类：**A 类** = 落入 dump 会话已知死区间的指针（旧 ntdll [0x7ffeeb320000, +0x300000) 为已证实死区间；其它 dump 会话模块基址若能从 T0.4 证据（`docs/XX21B_CORE_PERFECT_REPORT_20260829.md`、`xx21b_perfect_output/` 各 JSON）恢复，一并列入；恢复不了的如实标注"未能恢复，未清洗"）；
- 每个命中记录：文件偏移、所在节、**是否被重定位表覆盖**（解析候选 `.reloc`——pe crate 同款算法在 python 重实现，只读）、旧值、按偏移模式（+0x106390 等）推算的新值；
- 输出机器可读指针图 `pointer_map.json`（T0.5 harness 后续可消费）+ 人类可读报告。

### 2. Phase 2 — 外科手术式补丁（只动副本）

- 工作对象 = vault 原件的**副本** `lab/xx21b_pcell_clean/core_perfect_candidate_cleaned.dll`（vault 原件 3650ea6c **只读，一个字节不许动**——T016 红线沿用）；
- **裸数据槽**（无重定位覆盖）：旧值 → 当前会话对应值（ntdll 系 = 当前 ntdll 基址 + 同偏移；当前基址以**运行时读取为准**——从 T019/T018 泵 JSON 或开跑时自测进程枚举获得，写进指针图）；
- **重定位覆盖槽**：**不直接补当前值**（会被 loader 二次 delta 破坏）——按重定位语义处理：若该槽本应指向"候选映像外"的系统地址，正确做法 = 从重定位表中**移除该槽项**并直接写当前值（附 diff 证明 .reloc 相应条目同步删除）；若判断做不到安全处理 → 该槽**保持原样并标注"未清洗（重定位覆盖）"**，如实进报告，不许硬补；
- 每个补丁字节记录进指针图（offset/old/new/section/reloc_covered）。

### 3. Phase 3 — 离线验证（全部要真原始输出）

1. **复扫归零**：清洗后副本再扫，A 类死区间指针命中 = **0**；未清洗槽（如有）逐个列出并说明原因。
2. **补丁最小性**：`cmp` 原件 vs 副本，差异字节数 = 8 × 补丁槽数（+ .reloc 删除的字节数，逐条对账），无任何其它差异。
3. **结构完好**：DOS/PE 头、节数、节表、导出表（Run/GetAppVersion 地址解析不变）、`.text` 字节逐位不变（熵抽查）——全部与原件一致。
