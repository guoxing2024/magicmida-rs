文件: D:\Tools\RE\dumps\runtime\启动器_SUCCESS.exe

步骤1: 在崩溃位置设置断点
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 打开x64dbg
2. 加载启动器_SUCCESS.exe
3. 计算崩溃地址：
   ImageBase + 0xEDA071
   如果ImageBase = 0x140000000
   则崩溃地址 = 0x14EDDDA071
4. 在该地址设置断点: bp 14EDDDA071
5. 运行程序: F9

步骤2: 检查寄存器状态
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
当断点命中时，查看：
• rsi (source address) - 应该指向容器数据
• rdi (dest address) - 应该是HeapAlloc返回的有效地址
• rcx (count) - 应该是64

检查命令:
  r rsi
  r rdi
  r rcx

步骤3: 验证内存可访问性
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 检查source是否可读:
   dump rsi
   如果显示"???"，说明地址无效

2. 检查dest是否可写:
   dump rdi
   如果显示"???"，说明地址无效

3. 检查复制范围:
   dump rsi, rcx
   dump rdi, rcx

步骤4: 回溯到调用处
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 查看调用栈: Ctrl+K
2. 找到call memcpy的位置
3. 在那里设置断点
4. 重新运行，在调用前检查参数

步骤5: 验证关键计算
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
在call memcpy之前：

1. 检查r14 (metadata指针):
   r r14
   dump r14, 40
   
2. 检查data_offset:
   dd r14+10  (显示[r14+16]的值)
   
3. 验证source计算:
   lea rdx指令后: r rdx
   add rdx指令后: r rdx
   最终rdx应该 = stub_base + data_offset

4. 检查stub_base:
   stub_base RVA = 0xEDA000
   实际地址 = ImageBase + 0xEDA000

常见问题排查:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 如果rsi无效:
   - data_offset计算错误
   - 或stub_base地址错误
   
2. 如果rdi无效:
   - HeapAlloc返回了NULL
   - 但test/jz应该跳过了
   
3. 如果rcx太大:
   - metadata中的size字段错误

修复方向:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
根据调试结果：
• 如果是地址计算问题 -> 修复displacement计算
• 如果是数据问题 -> 重新生成metadata
• 如果是时机问题 -> 修改TLS callback逻辑
